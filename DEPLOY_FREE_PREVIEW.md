# Fresh free preview: Vercel, Render, Supabase

This creates a fresh database. It does not migrate or delete Railway data.
Use branch `review/anna-coach-integration` until the PR is reviewed.

## No-card local backend with Quick Tunnel

Keep the Vercel frontend and Supabase database/storage, and run the backend on
your computer. From the repository root, run:

```sh
backend/.venv/bin/python backend/start_supabase_preview.py --project-ref lvazxakcbixwwzrlyibb
```

Enter the **Session pooler URI**, database password, and backend secret/service-role
key at the hidden terminal prompts. The URI can retain `[YOUR-PASSWORD]`; the
separate password prompt URL-encodes the actual password correctly. Input is
kept in the backend process, never saved to `.env` or printed. Enter credentials
again after restarting the process. A new signing key also requires signing in
again; the Supabase data remains.

The command verifies TLS database access, creates `recordings` as a private bucket
if missing, and tests a real upload/download/delete cycle. It refuses an existing
public bucket. It then applies migrations, seeds questions only if empty, and
starts the API on `127.0.0.1:8014`. Keep the terminal open.

Once it prints **Supabase preview ready**, start a Quick Tunnel pointing to port
8014 and rebuild the Vercel preview with its public URL as `NEXT_PUBLIC_API_URL`.
Retain the stable Vercel alias already listed in `ALLOWED_ORIGINS`. Keep the old
preview running until the new connection is verified. Quick Tunnel URLs can
change on restart; update Vercel's build setting and redeploy when that happens.

This setup does not read developer `.env` files. Optional AI credentials can be
provided through the launching terminal's environment. Without them, speech or
feedback functionality remains unavailable as described below. Your computer,
backend, and tunnel must stay online.

## 1. Supabase

1. Create a **Free** project named `anna-speaking-coach`, preferably in Singapore
   or a nearby region. Generate and save the database password privately.
2. Under **Storage**, create a bucket named `recordings`. Keep **Public bucket
   disabled**. Do not add anonymous access policies. Allow uploads up to 20 MB.
3. Click **Connect**, choose **Session pooler** (port 5432), and copy the
   PostgreSQL URI. Replace the password placeholder with the URL-encoded database
   password and append `?sslmode=require`. The URI must start with
   `postgresql://`. Paste it only into Render's `DATABASE_URL` field.
4. Find the project URL and backend-only secret/service-role API key in the
   project's API settings. Use them only in Render's server environment.
   Never put the server key into Vercel, `NEXT_PUBLIC_*`, Git, or chat.

The app continues to use its existing FastAPI login and JWTs. Supabase supplies
PostgreSQL and private file storage, not a replacement authentication flow.
Migration `0004` enables row-level security without client policies on all
application tables, blocking Supabase's anonymous Data API access. FastAPI must
connect as the database owner via the session pooler.

## 2. Render

Create a Blueprint from `Chunporo/anna-speaking-coach`, selecting branch
`review/anna-coach-integration` and its root `render.yaml`. Verify that the
service is **Free** before creating it. The Blueprint uses the backend Dockerfile
and does not provision a Render database or disk.

Fill the prompted values directly in Render:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | Supabase session-pooler PostgreSQL URI with TLS |
| `SUPABASE_URL` | Supabase HTTPS project origin |
| `SUPABASE_SERVICE_ROLE_KEY` | Backend-only Supabase secret/service-role key |
| `ALLOWED_ORIGINS` | Exact Vercel preview origin; comma-separated if multiple |

`AUDIO_STORAGE=supabase`, `SUPABASE_AUDIO_BUCKET=recordings`, production mode,
and strict CORS are configured by the Blueprint. `SECRET_KEY` is generated by
Render. Automatic deployment is disabled; explicitly deploy tested commits.

Startup runs Alembic migrations, seeds questions only if the question table is
empty, and listens on Render's `PORT`. `/api/health` checks the database. New
recordings are uploaded to the private bucket before the session is committed;
temporary files are removed. Playback and deletion still require the owning
user's FastAPI token.

Set AI credentials separately in Render if available:

- `GOOGLE_CREDENTIALS_JSON`: Google Speech service account JSON.
- `GEMINI_API_KEY`: feedback provider key.
- `GOOGLE_CLIENT_ID`: optional Google sign-in, paired with the frontend client ID
  and its allowed origins in Google Cloud.

The image does not bundle local Whisper. Without a working transcription
provider, recording analysis returns an honest retryable error. Without Gemini,
successful transcriptions receive no fabricated grades.

## 3. Vercel

The project is `chunporos-projects/anna-speaking-coach`. Deploy the `frontend`
directory with Next.js, `npm ci`, `npm run build`, and output `.next`.

Set `NEXT_PUBLIC_API_URL` to Render's HTTPS base URL (without `/api`). Rebuild the
preview after changing it; this variable is embedded at build time. Ensure the
resulting preview origin is included in Render's `ALLOWED_ORIGINS`.

Use Vercel's **Root Directory = frontend**, or deploy with `vercel --cwd frontend`.
`frontend/vercel.json` explicitly configures Next.js and the `.next` output.
The older repository-root configuration is not the supported path for this
preview.

## 4. Verify

Check `/api/health`, register and log in, create a custom question, record an
answer, and verify authenticated playback. Restart the Render service and verify
playback again. Test unavailable-provider behavior separately. Do not call the
full speech/feedback flow verified without real provider credentials.

Run retention cleanup with `python database/cleanup_audio.py --days 30` to preview
eligible recording references; add `--apply` to delete the private objects while
retaining transcripts, feedback, and progress. Remote preview counts references,
including objects that might already have been removed.

## Free-tier limitations

- Render free services sleep after idle time and use an ephemeral filesystem.
  Supabase stores recordings durably; a cold start can delay the first request.
- Supabase free storage/database/egress quotas apply and low-activity projects
  can pause. Monitor usage and use the retention command as needed.
- Do not use Render's expiring free PostgreSQL for this setup.
- Free hosting does not imply free Google Speech or Gemini usage.
